데이터 품질을 높이기 위해 데이터셋 자체의 관련성을 보장하는 패턴(예: 감사-쓰기-감사-배포, AWAP)을 적용하곤 한다. 하지만 업스트림에서 데이터 흐름이 아예 차단되어 잡(Job)이 실행조차 되지 않는 상황이라면, 이러한 데이터 품질 해법만으로는 문제를 인지할 수 없다.

이러한 공백을 메우기 위해 시스템에 모니터링과 경고 기능을 추가하는 것이 '데이터 관찰 가능성 디자인 패턴'이다. 이 패턴은 탐지(Detection)와 추적(Tracking)이라는 두 가지 핵심 요소에 의존한다.

## 1\. 흐름 중단 탐지기

가장 심각한 데이터 문제 중 하나는 '데이터셋 비가용성'이다. 데이터가 없으면 잡이 실행되지 않아 다운스트림에서 데이터를 사용할 수 없게 된다. 예를 들어, 스트리밍 잡이 데이터를 동기화하다가 어느 날 레코드를 쓰지 않고 처리만 해버리는 경우가 발생할 수 있다. 잡 자체가 실패한 것이 아니기 때문에, 사용자가 데이터 부족을 불평하기 전까지는 문제를 알아차리기 어렵다. 이러한 데이터 비가용성 오류를 포착하여 신뢰성을 높이기 위해 '흐름 중단 탐지기' 패턴을 도입할 수 있다.

#### 데이터 수집 모드에 따른 구현

스트림 처리의 경우, 데이터 수집 모드에 따라 두 가지 접근 방식으로 나뉜다.

-   **지속적인 데이터 전달:** 1분이나 1초처럼 지정된 시간 단위마다 최소 하나의 레코드를 기대하는 방식이다. 지정된 시간 동안 새로운 데이터가 들어오지 않을 때마다 경고를 발생시킨다.
-   **불규칙한 데이터 전달:** 5분 연속 데이터가 들어오지 않는 등 오류와 무관한 전달 중단이 예상될 때 사용한다. 데이터가 없는 기간이 허용된 윈도(Window) 기간보다 길어질 때만 경고를 발생시킨다. 불규칙한 흐름에서 지속적인 전달 방식을 사용하면 너무 많은 경보가 울려 '경보 피로'로 이어질 수 있으므로 주의해야 한다.

#### 데이터 파이프라인 및 저장소 계층별 탐지

흐름 중단은 배치 파이프라인이나 정적 데이터베이스에서도 발생할 수 있으며, 이를 찾기 위해 다음과 같은 계층을 분석한다.

-   **메타데이터 계층:** 관찰된 테이블의 마지막 수정 시간 등 추가 정보를 활용한다. 예를 들어 매시간 수집되는 테이블이 1시간 이상 수정 시간의 변화가 없을 때 경고를 발생시킨다.
-   **데이터 계층:** 메타데이터 계층을 사용할 수 없거나 갱신 정보가 없을 때 유용하다. 수정 시간 컬럼을 직접 추가하거나, 특정 평가 시간 동안 레코드 개수를 세어 수치가 변하지 않는지 비교하여 흐름 중단을 감지한다.
-   **스토리지 계층:** 원시 JSON 파일이나 테이블 파일 등 스토리지 공간에 마지막 파일이 쓰인 시간을 모니터링한다. 임곗값 내에 갱신이 없으면 중단 경고를 올린다.

### 구현 시 주의해야 할 함정

흐름 중단 탐지기는 간단해 보이지만, 실제 구현 시 임곗값, 메타데이터, 거짓 양성(False Positive)과 같은 함정이 숨겨져 있다.

-   **임곗값 찾기:** 과거 관찰된 크기를 기반으로 임곗값을 정할 때, 마케팅 작업 등으로 인해 평소보다 많은 활동이 생성되는 경우 거짓 양성을 유발할 수 있다.
-   **메타데이터의 한계:** 스키마 진화 같은 메타데이터 변경 작업이 발생하면, 새로운 데이터 레코드가 추가되지 않았음에도 수정 시간이 갱신되어 흐름 중단 탐지를 방해할 수 있다.
-   **스토리지 거짓 양성:** 컴팩션(Compaction) 같은 유지 관리 작업은 기존 데이터 블록을 병합하여 새로운 파일을 생성하지만, 실제 새로운 데이터셋이 생성된 것은 아니므로 흐름의 연속으로 간주하면 안 된다.

### 실제 적용 예시

-   **Kafka와 Prometheus:** 카프카에서 매분 쓰이는 레코드 개수를 평가하는 표현식을 사용하고, 마지막 값이 0과 같을 때마다 그라파나(Grafana)가 데이터 중단 경고를 발생시키도록 설정할 수 있다.
-   **PostgreSQL:** track\_commit\_timestamp 구성 매개변수를 활성화하여 마지막 커밋 시간을 추출하고, 현재 시간과의 차이가 허용된 임곗값보다 클 때 알림을 트리거할 수 있다.
-   **Delta Lake 프로듀서:** 데이터 프로듀서 작업이 끝나면 마지막 갱신 시간 지표를 프로메테우스에 전송하여 데이터 수집 중단 여부를 확인할 수도 있다.
